# CLAUDE.md — context pointer

## Architecture docs first

Before exploring the codebase via Glob/Grep, read these — they are
authoritative and dramatically cheaper than rediscovering structure:

- **`docs/ARCHITECTURE.md`** — top-level system design, stack diagram,
  user-journey walkthroughs, contract index, hook index, storage,
  external integrations, critical invariants, debugging-cheatsheet.
- **`docs/CODEMAPS/<dir>.md`** — per-directory deep dives:
  - `hooks.md` — every hook in `packages/app/src/hooks/`
  - `screens.md` — every screen in `packages/app/src/blank-ui/screens/`
  - `components.md` — `blank-ui/components/` + `src/components/`
  - `lib.md` — `packages/app/src/lib/` utilities + ABIs + constants
  - `providers.md` — React context providers
  - `api.md` — Vercel serverless functions
  - `contracts.md` — every Solidity contract + storage layout
  - `hardhat-tasks.md` — deploy + upgrade + ops tasks

For wave / phase planning context, see `WAVE3_PLAN.md` (the build) and
`WAVE3_SETUP.md` (manual setup checklist + deferred items).

## Style & conventions (terse)

- No flowery language in commits; short subject + minimal body.
- Default to no comments; only add when WHY is non-obvious.
- Surgical changes — don't refactor unrelated code.
- UUPS upgrades: append-only storage; `pnpm storage:check` MUST pass.
- For FHE / crypto / multichain: read docs + source, never guess.
- Frontend signing: pass through `useEmailAuthSigner` (it handles both
  EOA and passkey-AA paths).
- Contract calls from frontend: prefer `useUnifiedWrite` /
  `unifiedWriteBatch` so the EOA + AA + paymaster modes are all handled.

## Refreshing the docs

After significant structural changes (new contract, new top-level
screen, new directory), regenerate the relevant codemap. The doc set
was generated by spawning 8 parallel Explore agents — one per major
directory — and assembling their structured outputs. A
`/update-codemaps` slash command can automate this.
